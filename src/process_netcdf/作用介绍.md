这两个文件是你原始 NetCDF 数据经过**不同处理流程**后生成的两个独立产物，分别服务于不同的下游用途。下面从多个维度详细对比：

---

## 一、核心区别总览

| 对比维度 | `scaled.nc` | `uv.nc` |
|----------|------------|---------|
| **包含的变量** | 4 个标量场（温度、气压、水汽、阵风） | 2 个矢量场（U 风、V 风） |
| **核心处理** | 归一化到 [0, 255] | 重命名 + 加 lev 维度 + 纬度翻转 + min/max 属性 |
| **数值是否改变** | ✅ 改变了（线性映射到 0-255） | ❌ 未改变（保留原始物理值） |
| **维度结构** | 与原始文件相同（无 lev 维度） | 新增了 `lev` 维度，`lat` 顺序反转 |
| **变量名** | 保持原始长名称不变 | 重命名为 `U`、`V` |
| **新增属性** | 无 | 每个变量增加 `min`、`max` 属性 |
| **典型下游用途** | 可视化渲染 / 机器学习输入 / 图像生成 | 气象分析 / 模式驱动 / 风场矢量绘图 |

---

## 二、`scaled.nc` 详解

### 做了什么

对以下 4 个标量变量分别做**线性归一化**：

```
Precipitable_water_entire_atmosphere_single_layer  → [0, 255]
Pressure_surface                                   → [0, 255]
Temperature_surface                                → [0, 255]
Wind_speed_gust_surface                            → [0, 255]
```

公式：`new = (old - min) / (max - min) × 255`

### 为什么这么做

1. **消除量纲差异**：温度单位是 K（~270-310），气压是 Pa（~95000-105000），水汽是 kg/m²（~0-80）。归一化后统一到同一数值范围，方便叠加显示或作为模型特征输入
2. **适配 8-bit 存储/显示**：255 对应 uint8 上限，可直接转为灰度图或伪彩色图
3. **保留空间分布形态**：线性映射不改变相对大小关系，高值区仍然高、低值区仍然低

### 没做什么

- ❌ 没有改变维度结构
- ❌ 没有重命名变量
- ❌ 没有翻转坐标
- ❌ 没有添加额外属性

---

## 三、`uv.nc` 详解

### 做了什么（按处理顺序）

#### ① 变量重命名
```
u-component_of_wind_planetary_boundary  →  U
v-component_of_wind_planetary_boundary  →  V
```
> 原始变量名太长，重命名后方便后续脚本引用和绘图标注

#### ② 添加 `lev` 维度
```python
# 原始: U(lat, lon)
# 处理后: U(lev=1, lat, lon)，其中 lev = [1.0]
```
> NCO 原始脚本用 `defineLev.nco` + `ncecat` + `ncks --no_rec_dmn` 三步实现，Python 中一行 `expand_dims` 等价。目的是让风场数据具有与其他多层数据一致的维度结构，便于后续合并或统一处理

#### ③ 纬度翻转
```python
# 原始: lat 从南到北 [-90, ..., 90]
# 处理后: lat 从北到南 [90, ..., -90]
```
> 很多气象可视化工具（如 GrADS、某些 GIS 软件）要求纬度从北到南排列。`ncpdq -a "-lat"` 就是做这件事

#### ④ 写入 min/max 属性
```python
U@min = U.min()   # 例如 -35.2
U@max = U.max()   # 例如 42.8
V@min = V.min()
V@max = V.max()
```
> 将极值嵌入文件元数据，下游程序读取时无需重新遍历整个数组即可获取范围信息，常用于：
> - 绘图时自动设置色标范围
> - 数据质量控制（检查异常值）
> - 归一化预处理（如果后续也需要对 U/V 做 0-255 映射）

### 没做什么

- ❌ **没有归一化**：U/V 保留原始物理单位（通常是 m/s）
- ❌ 没有修改经纬度坐标值本身（只翻转了排列顺序）

## 四、为什么要分成两个文件？

```
原始 file.nc
    ├── scaled.nc  ← 标量场（已归一化，用于显示/ML）
    └── uv.nc      ← 矢量场（保留物理值，用于分析/模式）
```

| 原因 | 说明 |
|------|------|
| **处理逻辑不同** | 标量需要归一化，矢量不需要；混在一起会导致 U/V 也被错误缩放 |
| **下游消费者不同** | 渲染引擎只需要 scaled.nc；数值模式/风场分析只需要 uv.nc |
| **文件大小优化** | 各自只包含需要的变量，避免单个文件过大 |
| **独立更新** | 如果只更新了温度数据，只需重新生成 scaled.nc，uv.nc 不受影响 |

## 五、快速验证命令

安装好 xarray 后，可以用以下代码检查两个文件的结构和内容：

```python
import xarray as xr

# 检查 scaled.nc
ds_s = xr.open_dataset("scaled.nc")
print("=== scaled.nc ===")
print(ds_s)                    # 查看维度、变量、属性
print(ds_s["Temperature_surface"].values.min(), ds_s["Temperature_surface"].values.max())  # 应接近 0 和 255

# 检查 uv.nc
ds_u = xr.open_dataset("uv.nc")
print("\n=== uv.nc ===")
print(ds_u)                    # 应有 lev 维度，lat 从大到小
print(ds_u["U"].attrs)         # 应包含 min, max
print(ds_u["lev"].values)      # 应为 [1.0]
```
